JavaScript:

- JavaScript is single-threaded, Synchronous language.

- Everything happens inside Execution context. (combination of memory and code component)

- Memory component = Variable Environment = key value pair of variable and function:
like a=10, function = {}
- code component = Thread of execution = one command execution (one by one)

-> undefined = special keyword
- when function execution starts the memory gets assigned to variable, initially the variables gets initializes with "undefined". then the actual value get assigned to it when the function is called. (variable and function gets initializes)
- Execution context created for it code component, it starts execution one by one line

-> Call Stack:
- to manage the execution of the tasks it will be useful.
- the function gets executed in call stack. 
- Call Stack Follows LIFO. (Last in First Out) : chapati box
- call stack known by other names:
1. Program stack
2. control stack
3. Runtime stack
4. Machine stack

Parameters vs Arguments: (in function)

Parameters:
- local variable passed inside the function
- while creating a function the variable passed in the function is called as parameter.
- ex. function myfun(para1,para2 ){
console.log("parameters", para1, para2);
}

Arguments:
- the actual value passed to the function while the function is calling.
- when calling function the actual values are passed to it called as Arugments.
- ex. function(arg1,arg2); // arguments;
//------------------------------------------------------------------------------

-> Normal function:

- Normal function declarations are hoisted.
- Normal functions create their own this context.
- Normal functions have access to the arguments object.
- Normal functions can be used as constructors with the new keyword to create object instances.
- Normal functions are better suited for methods, constructors, or when dynamic this binding is needed.
- ex. function a(){
console.log("normal function");
}
a();
//------------------------------------------------------------------------------
-> Arrow function:

- Arrow functions, however, do not have their own this and inherit it lexically from the surrounding scope.
- Arrow functions, being expressions, are not hoisted and cannot be accessed before initialization.
- Arrow functions do not have their own arguments object and require the use of rest parameters (...args) instead.
- Arrow functions cannot be used as constructors and will throw an error if used with new.
- Arrow functions are ideal for short, concise functions, especially as callbacks or when this binding is not required

ex. const a = ()=> {
console.log("arrow function");
}
a();
